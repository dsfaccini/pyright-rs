# pyright map for a Rust port

Research report from 2026-10-20, against pyright `f2e1a53` (1.1.414). Paths are relative to `packages/pyright-internal/src/`. No builds, tests or pyright runs were used.

Summary: the minimal set for a faithful `pyright --outputjson` check is about 135k lines of TypeScript, and about 105k of that needs a line-for-line port. Reusing ruff's parser would break identical output, so pyright's tokenizer and parser should be ported too.

## 1. Inventory

Method: a script followed every import from `pyright.ts`, the CLI entry: 178 files, 140.7k lines.

Line counts by subsystem:
- parser: 16.4k (3.6k of it generated Unicode tables)
- binder group: 11.8k
- code flow: 3.1k
- evaluator core: 43.6k (`typeEvaluator.ts` alone is 31.2k)
- evaluator helpers: 22.1k
- checker: 8.1k
- import resolution: 6.1k
- program/service/sourceFile: 7.7k
- shared utilities: 11.8k
- localization: 1.7k
- CLI entry: 2.5k

Not on the check path:
- About 5.8k lines are imported but never run for a check (`--verifytypes`, `--createstub`, background analysis, docstrings).
- About 22.5k lines are LSP-only: `languageService/`, `typeServer/`, `languageServerBase.ts`, `server.ts`, `commands/`. None is reachable from the CLI.

Minimal set, about 135k lines: about 105k (parser through checker) needs a faithful port; about 28k can be rewritten from behavior (utilities, import resolution, program, CLI). Typeshed (28 MB) and the English messages ship as data.

The big unit: the evaluator, its helpers and the code-flow engine call each other through the `TypeEvaluator` interface built in `createTypeEvaluator` (about 115 members). They form one block of about 69k lines that has to be ported before any type can be printed.

Threads: a single-threaded run uses no `worker_threads`. `--threads` uses `child_process.fork` in `pyright.ts` `runMultiThreaded`.

## 2. Port hazards, most expensive first

1. Evaluation order. Types are evaluated lazily as the checker walks each file. Circular cases use incomplete types guarded by generation counters. Speculative evaluation rolls back its cache writes: `SpeculativeTypeTracker`, 48 call sites. About 35 fixed limits change the result when hit, for example `maxReturnTypeInferenceStackSize=2`, `maxInferFunctionReturnRecursionCount=12`, `maxConvergenceAttemptLimit=256`. The port must keep the same recursion and call order.
2. Mutable, cyclic type objects. Types carry `shared`/`priv`/`props`/`cached` fields (`types.ts`). The analyzer writes `.shared.*` 269 times and `.priv.*` 105 times. `inferredReturnType`, `mro` and `synthesizeMethodsDeferred` are filled in lazily, and identity comparison (`===`) is used as a fast path. Rust needs an arena with interior mutability from day one.
3. Closure architecture. 402 nested functions share about 25 mutable variables, and the calls re-enter each other: one struct with `&self` methods and RefCell fields.
4. UTF-16 semantics. JSON ranges are in UTF-16 code units. Literals are truncated at 50 code units. Directory entries are sorted with `<`. Duplicate diagnostics are dropped by a key that includes `hashString`, a 32-bit hash of the message (`DiagnosticSink.addDiagnostic`); a collision silently loses a diagnostic, so the hash must match bit for bit. String literals can hold lone surrogates. Identifiers are normalized with JS `normalize('NFKC')`.
5. Sorting. `combineTypes` sorts union members with a comparator that is not a total order (two literals each return 1), so the order depends on V8's TimSort (inferred). Diagnostics are sorted on line and column only, so emission order breaks ties.
6. Insertion order. `SymbolTable` is a Map; there are 196 Maps and 108 Sets, so the port needs ordered maps throughout.
7. JS-only output. A catch for "Maximum call stack size exceeded" in `inferFunctionReturnType` (typeEvaluator.ts:21193). `internalTypeCheckingError` embeds the JS stack.
8. Heap-driven cache flush. `Program._handleMemoryHighUsage` throws away the evaluator when the heap is over 90% full. Check with `--verbose`, which prints "Emptying type cache".
9. Message formatting. `ParameterizedString.format` calls `String.replace` with a string argument, so `$&` and `$$` inside type names get interpreted.
10. Low cost: big integers, a few regexes, Unicode tables (regenerated by `build/generateUnicodeTables.py`), global id counters.

`maxCodeComplexity` is a config setting (default 768, minimum 768) in `configOptions.ts`, not a hardcoded counter.

## 3. Oracle

- Sample tests: 1,353 `.py` sample files run through `typeEvaluator1–8.test.ts` (1,259 tests) and `checker.test.ts` (74). `validateResults` only checks counts.
- Exact type checks: 3,731 `reveal_type(expected_text=…)` calls in 530 samples. A mismatch raises an error, so the printed type is checked exactly.
- `tokenizer.test.ts` (91) and `parser.test.ts` (31) check exact output.
- Unenforced: 2,776 "should generate an error" comments. Fourslash covers LSP only.
- `--outputjson` emits `{file, severity, message, range, rule}` per diagnostic plus a summary. It is the real oracle. Upstream already runs mypy_primer, which gives a real-world corpus.
- Existing dumpers: `dumpTokenInfo`, `dumpSyntaxInfo` and `dumpTypeInfo` in `common/languageInfoUtils.ts`, `formatControlFlowGraph`, and the `trace/` tool that captures evaluator events.
- Where to hook a TypeScript dumper: tokens and ignore comments in `SourceFile.parse`; parse tree in `Parser.parseSourceFile`; scopes and symbols after `binder.bindModule` in `SourceFile.bind`; flow nodes via `formatControlFlowGraph`; expression types after `checker.check()` via `getCachedType` plus `printType`, reading the cache only so the dump does not change evaluation order; diagnostics per phase, then the final filtered list.

## 4. Runtime dependencies

Must be replaced: `fs` with `@yarnpkg/fslib`/`libzip` (for `.zip`/`.egg` import roots); `child_process` (`fullAccessHost.ts` runs `python -I` to get search paths; `--threads` forks workers); `vscode-uri` (the JSON `file` field comes from it); `jsonc-parser`, `smol-toml`, `command-line-args`, `chalk`, `tmp`, V8 heap statistics.

Can be dropped: `vscode-languageserver`/`jsonrpc` (used only for cancellation and disposable types), `chokidar` (`--watch` only), `worker_threads` (only `isMainThread`), `source-map-support`.

## 5. Ruff's parser

Verdict: do not reuse it.
- Messages differ: pyright says "Expected expression" where ruff's `error.rs` says "Expected an expression". The parser uses 148 distinct messages, including Python-version checks.
- Offsets differ: ruff counts UTF-8 bytes; pyright counts UTF-16 units.
- Tree shapes differ: pyright has 78 node types and an error node with 16 recovery categories. About 105k downstream lines read these, and `printExpression` copies source text into messages.
- Pyright-only parsing: type comments, re-parsing of string annotations, `# type: ignore` / `# pyright: ignore` collection.
- Porting the parser is 16.4k deterministic, easily diffed lines. An adapter from ruff's tree would cost about the same and still differ.

## 6. Upstream churn

Measured on a fresh upstream clone, 2026-04-15 to 2026-10-19:
- 104 commits touch the check path. By month: Apr 3, May 6, Jun 16, Jul 8, Aug 23, Sep 29, Oct 20, rising.
- +18.5k / −5.1k lines on the check path.
- Busiest files: `typeEvaluator.ts` 49, `checker.ts` 18, `types.ts` 13, `typeUtils.ts` 12, `typeGuards.ts` 12, `binder.ts` 11.
- Largest change: a new overload-result subsystem (+2.7k), switched on by default in `program.ts`, plus periodic Pylance sync drops.
- Ongoing sync cost (inferred): about 3k changed lines a month in the core.

## Suggested port order and first milestone

Order: shared utilities and localization; tokenizer and parser; import resolver; binder and flow graph; type model and printer; evaluator, helpers and code flow as one unit; checker; diagnostic assembly; CLI JSON.

First milestone: a Rust tokenize/parse/bind pass of about 30k lines that emits token, tree, scope and flow dumps, plus `--outputjson` with parse and bind diagnostics. Diff it against the TypeScript dumper over typeshed, the samples and pydantic-ai. That exercises the UTF-16, ordering and message-format hazards before the 69k-line evaluator starts.

Decide before the milestone: the memory model for type objects and the string representation.
